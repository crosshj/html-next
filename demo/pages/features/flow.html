The `Flow` component provides a way to define executable (and somewhat constrained) JavaScript code that can be triggered by events or called directly. Flows are the core mechanism for handling business logic, state changes, and user interactions in the framework. They run in a controlled environment with access to global state and utility functions. ## Defining Flows Flows can be defined using script tags (recommended) or x-flow components: ```html SetData('count', state.count + 1); ``` ## Attributes | Attribute | Type | Required | Description | |-----------|------|----------|-------------| | `key` / `data-key` | string | Yes | Unique identifier for the flow | ## Utility Functions Flows have access to several utility functions for common operations. | Function | Description | Documentation | |----------|-------------|---------------| | `SetData` | Set a state value | [Details](/features/Flow/SetData) | | `Query` | Fetch content from URL (async function) | [Details](/features/Flow/Query) | | `Navigate` | Navigate to a new path | [Details](/features/Flow/Navigate) | | `Alert` | Show alert dialog (async function) | [Details](/features/Flow/Modal) | | `Confirm` | Show confirm dialog (async function) | [Details](/features/Flow/Modal) | | `Trigger` | Trigger another flow programmatically | [Details](/features/Flow/Trigger) | | `console.log` | Log to console | - | ## Global Variables Flows have access to all application state through the `global` and `state` objects (which are identical): | Variable | Type | Description | |----------|------|-------------| | `global` | object | Read-only copy of application state - access any property via `global.propertyName` | | `state` | object | Read-only copy of application state (identical to global) | | `event` | object | Event details when triggered by subscription | ### Accessing State Properties All state properties can be accessed through either `global` or `state` using standard JavaScript property syntax. **Important**: These are read-only copies - direct mutation will not affect the actual application state: ```javascript // Access any state property (both are identical) const currentPath = global.activePath; // or state.activePath const userData = global.user; // or state.user const pageContent = global.pageContent; // or state.pageContent const customData = global.myCustomProperty; // or state.myCustomProperty // ❌ DON'T DO THIS - direct mutation won't work state.foo = 'bar'; // This won't update the actual state global.bar = 'baz'; // This won't update the actual state // ✅ DO THIS - use SetData to update state SetData('foo', 'bar'); SetData('bar', 'baz'); ```
