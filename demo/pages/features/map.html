The `Map` component provides powerful template-based rendering for dynamic content generation from arrays of data. It processes data arrays and renders each item using a template with support for conditional rendering, loops, and dynamic content. The component automatically subscribes to state changes and re-renders when data updates, making it ideal for dynamic lists, tables, and other data-driven UI elements. ## Features - **Template Rendering**: Process data arrays with custom templates - **State Subscription**: Automatically updates when data changes - **Conditional Logic**: Support for `{{#if}}` and `{{#each}}` syntax - **Dynamic Content**: Access to item properties and array indices - **Nested Data**: Support for complex nested data structures - **Error Handling**: Graceful handling of missing or invalid data - **Performance**: Efficient rendering with minimal DOM updates ## Attributes | Attribute | Type | Required | Description | |-----------|------|----------|-------------| | `items` | string | Yes | State path to the data array | ## Usage ```html {{item_name}} - {{item_email}} ``` ## Basic List ### Simple List ```html {{item_title}} ``` **Description**: Renders a simple list of todo items with basic styling. ### Numbered List ```html {{index}}. {{item_task}} ``` **Description**: Creates a numbered list with index and item content. ### Styled List ```html {{item_title}} {{item_description}} ``` **Description**: Styled list with cards, shadows, and color hierarchy. ## Data Table ### Basic Table ```html User List {{item_name}} {{item_email}} {{item_role}} ``` **Description**: Creates a data table with headers and grid layout. ### Styled Table ```html Product Inventory {{item_name}} {{item_category}} {{item_price}} {{item_stock}} ``` **Description**: Styled table with alternating rows, colored headers, and conditional styling. ## Conditional Rendering ### Conditional Items ```html {{item_title}} (Pending) ``` **Description**: Only shows incomplete tasks with conditional display. ### Status-based Styling ```html Order #{{item_id}} {{item_status}} ``` **Description**: Orders with different background colors based on status. ## Nested Data ### Nested Object Access ```html {{item_name}} {{item_address.street}}, {{item_address.city}} {{item_contact.phone}} - {{item_contact.email}} ``` **Description**: Accessing nested object properties in the template. ### Nested Arrays ```html {{item_name}} • {{item_name}} ({{item_position}}) ``` **Description**: Nested mapping for departments and their employees. ## Template Logic ### Conditional Rendering with {{#if}} ```html {{item_title}} Priority: {{item_priority}} {{#if item_urgent}} ⚠️ URGENT TASK {{/if}} {{#if item_assignee}} Assigned to: {{item_assignee}} {{/if}} ``` **Description**: Shows additional content only when specific conditions are met using `{{#if}}` blocks. ### Comprehensive {{#if}} Examples ```html {{item_name}} {{item_email}} {{#if item_isActive}} Active {{/if}} {{#if item_department}} Department: {{item_department}} {{/if}} {{#if item_skills}} Skills: {{#each item_skills}} {{this}} {{/each}} {{/if}} {{#if item_profile}} {{#if item_profile.avatar}} Has profile picture {{/if}} {{/if}} ``` **Description**: Comprehensive example showing `{{#if}}` with boolean properties, string existence, array checks, and nested object properties. ### Nested Loops with {{#each}} ```html {{item_name}} {{item_description}} {{#if item_tags}} {{#each item_tags}} {{this}} {{/each}} {{/if}} {{#if item_milestones}} Milestones: {{#each item_milestones}} {{this_name}} Due: {{this_dueDate}} {{#if this_completed}} ✓ Completed {{/if}} {{/each}} {{/if}} ``` **Description**: Combines `{{#if}}` conditionals with `{{#each}}` loops to handle complex nested data structures like project tags and milestones. ### Chart Cards with Conditional Chart Types ```html {{item_title}} {{#if item_chartType}} {{#if item_chartType === 'line'}} {{/if}} {{#if item_chartType === 'pie'}} {{/if}} {{#if item_chartType === 'bar'}} {{/if}} {{/if}} ``` **Description**: Eliminates repetitive chart card markup by using conditional rendering to show different chart types based on data. A single template handles line charts, pie charts, and bar charts with identical wrapper styling. ## Dynamic Content ### Dynamic Styling ```html {{item_name}} {{item_value}} / {{item_target}} ``` **Description**: Dynamic background colors based on performance metrics. ### Interactive Elements ```html {{item_name}} {{item_buttonText}} ``` **Description**: Interactive elements with dynamic button actions. ## Empty State ### Empty List Handling ```html No users found Add some users to get started {{item_name}} - {{item_email}} ``` **Description**: Shows empty state when no data is available. ## How It Works ### Data Processing 1. **Data Retrieval**: Gets data array from state using the `items` attribute 2. **Array Validation**: Checks if data is an array and has items 3. **Template Processing**: Processes the template for each array item 4. **Content Generation**: Creates HTML content for each item 5. **DOM Update**: Updates the component's innerHTML with generated content ### Template Syntax 1. **Item Access**: `{{item_propertyName}}` accesses item properties 2. **Index Access**: `{{index}}` provides the current array index 3. **Conditional Logic**: `{{#if condition}}...{{/if}}` for conditional rendering 4. **Loop Logic**: `{{#each array}}...{{/each}}` for nested loops #### Conditional Syntax Details - `{{#if item_propertyName}}` - Shows content if property exists and is truthy - `{{#if item_isActive}}` - Shows content if boolean property is true - Content between `{{#if}}` and `{{/if}}` is only rendered when condition is met - Multiple conditions can be nested for complex logic #### Loop Syntax Details - `{{#each item_arrayProperty}}` - Iterates over an array property of the current item - Inside `{{#each}}` blocks, use `{{this}}` for primitive values (strings, numbers) - For object arrays, use `{{this_propertyName}}` to access object properties - Loops can be nested and combined with conditionals for complex templates ### State Subscription 1. **Automatic Subscription**: Subscribes to data path for changes 2. **Re-rendering**: Automatically re-renders when data changes 3. **Cleanup**: Unsubscribes when component is disconnected 4. **Performance**: Only re-renders when the specific data path changes ## Best Practices ### Data Structure - Use consistent data structures across your application - Keep data arrays focused and single-purpose - Avoid deeply nested structures when possible - Use meaningful property names for better template readability ### Performance - Avoid extremely large datasets that could impact rendering - Use specific data paths to minimize unnecessary re-renders - Consider pagination for large datasets - Test rendering performance with various data sizes ### Template Design - Keep templates simple and focused - Use consistent styling across all items - Test templates with different data structures - Consider accessibility in template design ### Error Handling - Always provide fallback content for missing data - Test with empty arrays and null values - Use conditional rendering to handle edge cases - Monitor console for template processing errors ## Common Use Cases - **Dynamic Lists**: User lists, product catalogs, and content feeds - **Data Tables**: Tabular data display with sorting and filtering - **Dashboard Widgets**: Dynamic content based on user data - **Form Options**: Dynamic form fields based on configuration - **Navigation Menus**: Dynamic menu items based on user permissions - **Content Feeds**: News feeds, activity streams, and notifications - **Search Results**: Dynamic search result display - **Configuration Panels**: Dynamic settings and options display
